# 盐憩五分钟演讲稿

大家好，我今天展示的项目叫《盐憩》。

盐憩是一个潜水旅游主题的多页面前端项目，但它不是普通旅游信息站，也不是电商预订页或后台表单系统。这个项目真正想做的，是把“进入海、理解海、把海收进行程”做成一段连续的品牌体验。用户不是在几张普通网页之间切换，而是像在同一片海里，从门厅进入海面，再下潜到具体海域和行程空间。

我在做这个项目时，先确定了项目的气质：深海、安静、高级、舒缓、沉浸、有空间层级。

“盐”代表海水、潮汐、海风，也代表潜水这件事最直接的环境感。“憩”代表停驻、休息和慢下来。所以盐憩不是一个强调快速搜索、立即下单的网站，而是希望用户先靠近海，再读懂海，最后把适合自己的那片海慢慢收进行程。

基于这个定位，我把页面关系设计成海层关系。

`index.html` 是潜前门厅。用户第一次进入时，看到的不是普通登录框，而是一层静水入口。用户可以登录，也可以选择“带上一段航线”，带着一段完整路线进入首页主线。

`home.html` 是海面第一层。首页的任务不是把信息马上堆出来，而是先让用户被海吸引。今日海域、海域陈列、Dive Match 和品牌故事，分别承担“看海、选海、判断哪片海适合我”的过程。这里的卡片和推荐不是普通目的地货架，而是围绕潜水节奏、海域气质和用户状态展开。

`detail.html` 是进入一片具体海域。它不是普通景点详情页，而是海域档案。页面里有 Sea Dossier，让用户先读懂这片海的位置、季节、生物和注意事项；有 DIVE READINESS，用来判断证书水层和近期下潜状态；还有 Sea Atlas，这是详情页最重要的技术展示点。Sea Atlas 不是普通地图截图，而是基于 Leaflet 和本地离线地图包做出来的海图系统，能展示潜点、出发点、靠近路线和水下结构，并支持全屏查看和返回航线档案。

详情页右侧的 Dive Brief 也不是电商购买栏。它更像一个潜水简报，负责把当前适配、航线参考、套餐节奏和收进行程的动作稳定放在旁边。用户点击“展开这套安排”可以查看更完整的安排；确认后，这片海会被写入行程页，而不是变成普通下单成功页面。

`trip.html` 是更深一层的规划空间。这里我没有把它做成普通表单，而是设计成 Planner Desk。现在这个页面的主线很清楚：Planner Desk 负责编辑草稿，已收进行程负责切换已经确认的海域，Sea Brief 负责查看当前这一程的最终摘要。这样用户能理解自己是在“写草稿、收住海域、查看简报”，而不是面对一堆重复的流程卡。

项目还有三张信息页：`contact.html`、`terms.html` 和 `privacy.html`。它们没有退回普通文档页，而是被设计成更浅、更静的说明水域。联系页里的留言叫站内留言回声，会先保存在当前浏览器里；协议和隐私页则用同一套潮线目录、玻璃壳体和深度计语言，保持和主线页面一致。

整个项目里，我认为最有辨识度的系统是深度计系统。

深度计不是装饰，而是整站空间语言。它会随着页面、滚动和跨页跳转变化，让用户知道自己现在处在哪一层海里。页面过渡也不是普通 fade，而是根据语义做下潜、上浮或相邻海域之间的潜游。

从技术实现上看，这个项目主要使用 HTML、CSS 和原生 JavaScript。页面样式按页面拆分，首页、详情页、行程页和信息页都有自己的样式文件。交互逻辑也按职责拆开，比如 `home.js` 管首页卡片与推荐，`detail.js` 管 Sea Atlas、套餐和详情交互，`trip.js` 管 Planner Desk 和 Sea Brief，`yanqi-trip-store.js` 负责详情页与行程页之间的共享状态，`depth-manager.js` 负责深度计和跨页过渡。

状态方面，因为项目是纯前端站点，我使用 `localStorage` 和 `sessionStorage` 来维持体验连续性。例如 Planner Desk 草稿、已收进行程、详情页确认过的套餐，以及联系页的站内留言回声，都会留在当前浏览器里。这样用户从 detail 进入 trip 时，页面不会断掉，而是能继续接住刚才那片海。

最后，我想用一句话收住这个项目。

盐憩想表达的，不只是“哪里可以潜水”，而是“怎样让用户在浏览、选择和规划之间，慢慢进入一片更适合自己的海”。我做这个项目时最在意的，也不是单个页面多炫，而是每个功能是否都留在盐憩的世界观里：深海、安静、舒缓，并且有清楚的空间层级。

谢谢大家。
